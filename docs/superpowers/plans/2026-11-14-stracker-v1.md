# stracker v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Android app that records a day automatically (phone use per app, movement, GPS path, sleep, work, travel) and by one-tap logging, and shows it as a month calendar with a tap-through day timeline.

**Architecture:** A fork of Ostrava's Android app, stripped to its foundations (Compose + Material 3 design system, Room, DataStore, WorkManager, foreground service, osmdroid, JSON backup, Roborazzi screenshot tests, GitHub Actions CI). Raw signals are appended to Room by a single foreground collector service and never rewritten; a pure, unit-tested inference layer turns `signals + overrides + settings` into per-day episodes; Compose screens render a month calendar, a day timeline, a quick-log sheet, settings and onboarding.

**Tech Stack:** Kotlin 2.0.21, Jetpack Compose (BOM 2024.12.01), Material 3, Navigation Compose, Room 2.6.1 + KSP, DataStore Preferences, WorkManager 2.9.1, play-services-location 21.3.0 (FusedLocation + ActivityRecognition Transition API), osmdroid 6.1.20, JUnit 4 + Robolectric 4.14.1 + Roborazzi 1.40.1. JDK 17, AGP 8.7.3, compileSdk/targetSdk 35, minSdk 26.

**Spec:** `docs/superpowers/specs/2026-11-14-stracker-design.md` (mockups in `docs/superpowers/specs/mockups/`).

## Global Constraints

- Package `com.oblonian.stracker`, application id `com.oblonian.stracker`, app name `stracker`, repo `oblonian/stracker`. Ostrava repo is not modified.
- minSdk 26, targetSdk 35, compileSdk 35; JDK 17; builds must pass on GitHub Actions (`ubuntu-latest`) with no Android Studio.
- Data never leaves the device except through the explicit backup export; the only network use is OpenStreetMap tiles when a day's map is opened.
- Exactly one notification: the collector service's, on a channel of `IMPORTANCE_MIN`, silent, static text `stracker is tracking`, never updated. No other notification is ever posted.
- Battery-optimisation exemption is asked for once, in onboarding, never re-prompted; its status is shown only in Settings.
- No GPS requests while motion is STILL. Battery target < 3 % per day on the owner's realme 9 Pro+ (Android 14).
- All inference thresholds live in `domain/Thresholds.kt` with the spec's values: `SLEEP_MIN = 3h`, `SLEEP_GAP_MAX = 10min`, `NAP_MIN = 40min`, `WORK_GAP_MAX = 5min`, `WALK_EXERCISE_MIN = 20min`, `TRAVEL_WALK_MIN_METERS = 400.0`, `PLACE_VISIT_MIN = 5min`, defaults `SLEEP_WINDOW = 21:00–11:00`.
- A night's main sleep belongs to the wake-up day; a calendar day runs wake-up to wake-up; fallback to local midnight–midnight when no main sleep is found.
- Raw signal tables are append-only. Episodes are always recomputed from signals + overrides; user corrections live in `overrides` and are never lost by re-running inference.
- Every screen follows the approved mockups and Ostrava's design system; nothing else is added to the calendar or day screens.
- Tests: unit tests for all inference as pure functions; Robolectric for Room and collectors' parsers; Roborazzi screenshots for calendar, day view, quick-log, settings, onboarding written to `app/build/screenshots/`.
- Commit after every task with a message in the form `feat: …` / `chore: …` / `test: …`, ending with the attribution line this session requires.

## Review Focus

1. **A DST or time-zone change inside a day** (a 23 h or 25 h day, or the phone crossing a zone): day windows must still be contiguous, no instant counted twice or dropped. Test in Task 4 (`DayBoundariesTest.dst change day is 25h and contiguous`).
2. **The collector was killed overnight** (realme), so there are no motion transitions and no screen events between 23:00 and 07:00: sleep must still be inferred for that stretch. Test in Task 6 (`SleepInferenceTest.no data at all overnight is treated as still`).
3. **The step counter resets** (reboot) so the cumulative count drops: daily steps must be the sum of positive deltas, never negative, never a huge jump. Test in Task 8 (`StepsTest.counter reset after reboot does not produce negative or inflated steps`).
4. **Usage-access permission is missing or revoked**: `UsageStatsManager` returns empty or throws `SecurityException`; the poller must record nothing, not crash, and the day view shows no phone data. Test in Task 9 (`UsagePollerTest.missing permission records nothing and does not throw`).
5. **An ongoing manual episode overlaps automatic blocks**: automatic episodes must be clipped around it, never shown underneath or doubled in totals. Test in Task 8 (`InferenceEngineTest.auto episodes are clipped around a manual episode`).
